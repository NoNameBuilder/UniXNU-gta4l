# Handoff ABI: DarwinBoot → XNU

## Registers at the jump

`Entry.S:DarwinEnter` (`DarwinBootPkg/Driver/Entry.S`):

| register | value |
|---|---|
| `x0` | boot args physical address |
| `x1` | kernel entry physical address = `Address + Entry - Base` |
| `x2` | window base PA (`Address`) |
| `x3` | window size (1.5 GiB) |
| `x4` | framebuffer PA (`Video[0]`, even) |
| `x5` | framebuffer bytes (`rowBytes * height`) |

Before `br x1` it does: `daifset #15`, paint the green bar, `dc civac` the whole
kernel range, `ic iallu`, `sctlr_el1 &= ~(M | A | I)`, `tlbi vmalle1`, `isb`.
So XNU enters with the MMU **off**, alignment checks **off**, D/I caches
**invalidated**, interrupts **masked**, at EL1.

## `boot_args` (arm64, `pexpert/pexpert/arm64/boot.h`)

| offset | field | our value |
|---|---|---|
| `0x00` | `Revision` u16 / `Version` u16 | 2 / 2 |
| `0x08` | `virtBase` | lowest segment VA `0xfffffff00427c000` |
| `0x10` | `physBase` | window PA (`0x89e7c000` for the current artifact) |
| `0x18` | `memSize` | `0x60000000` |
| `0x20` | `topOfKernelData` | `Address + Used` |
| `0x28` | `Boot_Video` (6 × u64) | see below |
| `0x58` | `machineType` u32 | 0 |
| `0x60` | `deviceTreeP` | `virtBase + (TreeAddress - Address)` |
| `0x68` | `deviceTreeLength` | ADT size |
| `0x6c` | `CommandLine[1024]` | see below |
| `0x470` | `bootFlags` | 0 |
| `0x478` | `memSizeActual` | `0x60000000` |

`Boot_Video` is *not* `PE_Video`:

| offset | field |
|---|---|
| `0x28` | `v_baseAddr` (framebuffer PA, **bit 0 set** as the "physical, needs mapping" flag) |
| `0x30` | `v_display` |
| `0x38` | `v_rowBytes` (4800) |
| `0x40` | `v_width` (1200) |
| `0x48` | `v_height` (2000) |
| `0x50` | `v_depth` (32) |

`pexpert/arm/pe_init.c:419-429` copies these into `PE_state.video` and decodes
rotation/scale out of `v_depth`. `initialize_screen()` strips the low bits with
`& ~3UL`, and if bit 0 was set it treats the value as a physical address and
maps it itself (`ml_io_map_unmappable` → `kmem_alloc` + `pmap_map`). That path
needs `startup_phase >= STARTUP_SUB_KMEM`, which is why the framebuffer is not
reachable at the very first C instruction.

## Command line

```
serial=3 debug=0x14e keepsym=1 -v amfi_get_out_of_my_way=1 cs_enforcement_disable=1
fb-base=0x5c000000 fb-width=1200 fb-height=2000 fb-stride=4800 panel-rot=270
```

`debug=0x14e` selects verbose kprintf but also makes a panic **spin** instead of
rebooting — keep that in mind when a boot looks like a hang.

The `fb-*` arguments are informational for humans: XNU takes the framebuffer
from `boot_args.Video`, not from the command line.

## Device tree

The ADT is generated by `scripts/make-gta4l-adt.py` and copied into the window at
`TreeAddress`. Its VA is computed against `Kernel.Base`, so the tree is readable
before and after `arm_vm_init` without a separate mapping. Minimum content the
kernel checks before console init: `/chosen` with `dram-base`/`dram-size`,
`/chosen/memory-map`, `/defaults`, `/cpus`. Everything else is optional until
IOKit starts (see the table in `build/probe/AUDIT.md`).

## What the kernel does with it

`osfmk/arm64/start.s`: `_start_first_cpu` → `mov x20, x0` (args), builds
bootstrap page tables, derives `PTE`/`TTBR1` from `virtBase`/`physBase`, and
enables the MMU at `0xfffffff0073f1350` with a value built in `x0`
(`0x593d3454`). After that `common_start` returns to `_start` → `arm_init`
with the kernel mapped at its link address.

`memSize = 1.5 GiB` drives `PAGE_SHIFT_CONST = PAGE_MAX_SHIFT` (16 KiB pages);
the same branch is used on every non-Apple arm64 platform with > 1 GiB, so it is
not gta4l-specific.
